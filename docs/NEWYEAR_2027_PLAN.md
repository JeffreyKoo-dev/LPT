# 2027 신년운세 상품 기획서 (QuestofMe / LPT)

작성: 2026-10-24 · 목표 공개: 2026-12-01 (신년 수요 12~2월, 점신·포스텔러 기준 약 +20%)

## 1. 현재 상태 (코드 확인 결과)
- `yearly_fortune` "올해의 운세" 3,000원, 보석 전용, Haiku 4.5, 한 번 생성 후 캐시, 연 1회 구매.
- 결과 화면은 6~9문장 한 덩어리 텍스트. 신년 시즌 상품으로 내놓기엔 분량·구성이 약함.
- **연도 기준이 "현재 달력 연도"로 고정**: 클라이언트 `calculateYearlyFortune`, `hasPurchasedThisYear`, Edge Function `getCurrentYear()`/`startOfYear` 모두 `new Date().getFullYear()`.

## 2. 먼저 고쳐야 할 구조 문제 (출시 전 필수)
1. **대상 연도 파라미터화.** 12월에 "2027 운세"를 팔려면 연도를 "올해"가 아니라 상품 설정(`target_year=2027`)으로 받아야 한다. 지금 구조로는 12월 판매분이 2026년 운세로 생성된다.
2. **연말연시 시간대 불일치.** Edge Function(Deno)은 UTC 기준 연도, 사용자는 KST. 12/31 15:00~24:00 UTC 구간(= KST 1/1 0~9시)에 클라이언트는 2027, 서버는 2026으로 판단해 "결제 내역 없음(402)"이나 캐시 오판이 날 수 있다. 신년 첫날 새벽이 최대 트래픽이라 반드시 `Asia/Seoul` 기준으로 통일.
3. **재구매 규칙.** 2026년에 "올해의 운세"를 산 사용자가 2027 운세를 살 수 있어야 한다(연도별 구매 여부 판정: `product_code + target_year`).
4. **세운 기준 안내.** 사주에서 한 해의 경계는 입춘(2027-02-04경)이다. 엔진은 달력 연도 기준이므로 화면에 "양력 2027년(정미년) 기준 흐름" 문구를 넣고, 입춘 이야기는 짧은 각주로 처리(콘텐츠 결정 필요).

## 3. 상품 구성안

가격 결정 원칙: 지금 3,000원은 점신·포스텔러의 신년 유료 풀이 가격대(수천 원)와 비슷하다. 먼저 분량을 늘려 같은 가격에 체감 가치를 올리고, 계측 전환율을 본 뒤 가격 시험(3,000 vs 3,900)을 한다.

## 4. 원가 (추정, 가정 명시)
- 구현 기준: 출력 한도 3,500토큰. Haiku 4.5를 입력 약 2,000토큰·출력 최대 약 3,000토큰으로 가정하고 단가를 입력 $1/백만, 출력 $5/백만으로 두면 호출당 약 $0.017(약 25원). 단가는 Anthropic 가격표로 재확인 필요.
- 즉 AI 원가는 판매가의 1% 안팎이라 가격 결정 요인이 아니다. 실제 비용은 PG 수수료, 부가세, 환불 리스크다.
- 시즌 트래픽 폭주 대비: Edge Function 동시 호출 한도, Anthropic 요청 한도 확인 필요(미확인).
